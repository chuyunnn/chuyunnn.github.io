https://github.com/instructkr/claw-code

核心文件：

  • main.tsx：803KB，应该是编译打包后的入口
  • AgentTool.tsx：233KB，Agent 工具的核心实现
  • insights.ts：115KB，洞察分析模块
  • QueryEngine.ts：46KB，查询引擎
  • Tool.ts：29KB，工具基类

其中tools里有40多种工具，有bash执行、文件操作、代码搜索、MCP集成、任务调度等。每个工具都是一个独立的能力单元。

skills目录里有17个内置skills，包括remember、stuck、loop、batch、debug等

tools/AgentToll里面有6个内置agent

==>

每个Agent都有自己的职责边界 ==> 明确禁止使用某些工具

  1. General Purpose Agent：一个通用agent，什么都会一点，处理大多数常规任务。复杂任务会被调度给其他agent
  2. Explore Agent：明确限制只读，专门用来搜索代码库，严格禁止任何文件修改
  3. Plan Agent：明确限制只读，架构规划型agent，用来设计实现方案
  4. Verification Agent：不是设计测试用例来确认代码能工作，而是试图破坏代码【对抗检测，每次pass都需要给出证据】，并且列出了容易犯错的模式（比如会偷懒）
  5. Claude Code Guide Agent：内置的帮助系统，帮助学习claude code
  6. Statusline Setup Agent：负责IDE状态栏的显示设置，是cc和IDE集成很关键的一环

💡 好的 Agent 不是无所不能，而是知道自己的边界在哪里。

其他：

  • 动态system prompt拼接：源码里有一个 systemPromptManager，管理着 110 多条碎片化的系统提示词片段。这些片段会根据当前环境动态拼接成一个完整的 prompt。比如在 macOS 上运行时，会拼接 macOS 相关的文件路径约定；在调试模式下运行时，会拼接额外的调试指令；在处理 Git 相关任务时，会拼接 Git 操作的安全提示。

==> 每次调用都是在不同的上下文环境里，动态调整agent的行为【细粒度控制】

  • Dream Memory：源码里把记忆整理分成四个阶段，模拟 REM 睡眠

    • 碎片收集：把最近的对话片段、代码变更、用户反馈都捞出来。这个阶段不做事后诸葛亮，只管收集原始素材。

    • 关联分析：找出这些碎片之间的联系。比如用户之前问过的一个配置问题，可能和现在遇到的一个报错是同一个根因。Dream Memory 会把这些关联起来。

    • 知识萃取：把碎片化的信息提炼成可复用的知识点。

    • 记忆索引：把萃取出来的知识点存到向量库里，供后续检索使用。

这好的 AI 系统不只是能回答问题，而是能在你不问的时候悄悄学习。
