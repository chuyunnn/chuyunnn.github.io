很类似于cc啊，本质上就是用自然语言驱动工具完成任务（对接大模型）。可以在本地电脑或者云服务器上，通过IM工具（飞书、钉钉）进行管理

Claw 名称 类型 部署方式 核心优势 适合人群
OpenClaw 开源原生 本地 / 自建 完全自由、隐私、生态强 开发者、极客、深度定制
ArkClaw 商业 SaaS 云端 零部署、7×24、飞书集成 普通用户、企业、办公
QClaw 商业本地 本地一键 微信 / QQ 遥控、隐私 微信用户、远程控制
KimiClaw 社区衍生 本地 Kimi 深度集成、长文本 文档 / 代码工作者
PicoClaw 社区衍生 本地 / 嵌入式 超轻量、低资源 嵌入式、低配置设备
ZeroClaw 社区衍生 本地 零代码、可视化 非技术、快速搭建
AutoClaw 本地 开箱即用，飞书集成 大众用户、办公、快速上手

我现在的问题在于没有api，仍在使用免费的codex :)

hook：事件发生的时候，自动执行一段预设逻辑的功能（系统自动触发）

skill：识别到意图之后，可以自动加载skill，按步骤执行，不需要现想

[!NOTE]

启动会话时，只加载skills的元数据，让模型快速发现有哪些技能可以使用

用户意图匹配到某个skill，加载完整的skill.md正文，读取具体的执行指令

如果需要参考资料或者脚本，读取references/下的文件或运行scripts/里的脚本 ==> 脚本用于执行，而不是加载进上下文，因此token消耗不会随着skills的数量线性增长

整理一下核心逻辑：不要只执行 npm uninstall -g openclaw，这样卸载不干净，容易残留状态、配置、插件缓存，后面重装时可能遇到端口占用、配置冲突、插件加载失败。

正确姿势分三步。

第一步：先停掉 Gateway 服务，最好先看状态：

如果 Gateway 还在跑任务，直接停掉可能会丢数据，所以最好先确认已经 stopped 再继续。

第二步：执行官方卸载命令：

这个命令会进入交互式选择，文章里的建议是直接空格全选，然后回车确认。它主要会做这些事：

  • 停止并卸载 Gateway 服务
  • 删除 ~/.openclaw/ 状态目录
  • 清理工作区配置
  • 移除插件和缓存

第三步：移除全局 CLI 包：

如果你当时不是用 npm 装的，对应换成：

遇到权限问题再加 sudo。

卸载后可以再检查一下是不是已经清干净：

如果都返回空，或者提示 not found，基本就算卸干净了。

~/.openclaw/ 之所以重要，本质上因为这里存的是本地状态和运行痕迹；如果只删全局包，不清这个目录，就可能把旧配置、旧插件缓存、旧工作区信息留到下一次安装里。

如果 openclaw uninstall 不可用，再手动清理这些位置：

  • 二进制：/usr/local/bin/openclaw
  • 状态目录：~/.openclaw/
  • 服务：
    • macOS 用 launchctl
    • Linux 用 systemctl
