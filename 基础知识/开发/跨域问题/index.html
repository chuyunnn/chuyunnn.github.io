跨域问题

Created2026-01-28|Updated2026-01-28|基础知识开发
|Post Views:

问题定义

跨域，就是浏览器出于安全，禁止一个域名下的前端页面，去请求另一个 “不同域名 / 端口 / 协议” 的后端接口

  • 它不是后端的限制，也不是网络的限制，完全是浏览器强加的安全规则，叫 同源策略（Same-Origin Policy）
  • 只有浏览器有跨域限制，后端之间调用、Postman、curl 等工具，都没有跨域问题

浏览器定义“同源”非常严格，必须 协议、域名、端口 三者完全一致。只要有一个不同，就是跨域：

假设前端地址是：http://localhost:8080

请求的目标 URL 是否跨域 原因
http://localhost:8080/api/user 否 完全一致（同源）
https://localhost:8080/api/user 是 协议不同（http vs https）
http://127.0.0.1:8080/api/user 是 域名不同（localhost vs IP）
http://localhost:9000/api/user 是 端口不同（8080 vs 9000）

💡 浏览器为什么要做跨域限制？

  1. Cookie 被盗用，越权操作

登录银行网站 bank.com，浏览器保存了登录 Cookie ==> 打开恶意网站 evil.com

  • 如果没有跨域限制，evil.com 可以直接用浏览器里的 Cookie，去请求 bank.com 的转账接口，然后就被盗刷了
  1. 窃取敏感页面数据

恶意页面可以直接读取已登录的邮箱、社交网站的 DOM 内容和接口数据，造成信息泄漏

解决方法

方案 1：后端配置 CORS（最标准、生产首选）

CORS = Cross-Origin Resource Sharing，跨域资源共享

原理：后端在响应头里加上允许跨域的声明，浏览器看到后，就放行这个请求

Spring Boot 项目最常用的两种写法：

方式 A：全局配置类

方式 B：使用 @CrossOrigin 注解（单个接口）

方案 2：开发环境用代理（前端解决，仅限开发）

Vue / React / Vite / Webpack 都自带代理功能

原理：前端请求自己的地址 → 本地开发服务器转发给后端 → 浏览器认为是同源，不拦截
