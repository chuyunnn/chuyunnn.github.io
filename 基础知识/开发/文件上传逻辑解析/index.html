分片上传并存储分片到minIO

@PostMapping("/chunk")，controller接收参数：

  1. 首先进行文件类型验证：不支持压缩包、图片、视频、数据库文件这些
  2. 获取用户的组织标签信息。如果前端未给出，就去查找用户的主组织标签
  3. 调用service进行分片上传

  • 检查数据库文件表中是否存在该MD5信息

    • md5、文件名、文件总大小、上传状态、用户id、组织标签信息、是否公开

  • 检查分片是否已经上传（根据MD5、分片号、userId查询）

    • 根据redis key：String redisKey = "upload:" + userId + ":" + fileMd5;查询
    • 没有：
      • 构建minio存储路径：storagePath = "chunks/" + fileMd5 + "/" + chunkIndex;
        • (minio中不维护组织标签信息，要查去数据库取)
      • 存储到minio
      • 标记分片为已上传
    • 有：
      • 检查数据库中是否存在分片信息，如果没有：
        • 构建存储minio路径：storagePath = "chunks/" + fileMd5 + "/" + chunkIndex;
        • 检查minio是否存在该分片，如果不存在，需要重新上传（把标记“是否上传”的boolean值改为false）

  • 需要确保数据库chunkInfoRepository中存在分片信息，执行存储fileMd5, chunkIndex, chunkMd5, storagePath

    • 这个storagePath存储的是minio中的分片路径
  1. 检查所有分片是否上传成功：
  • 获取已上传分片列表
    • 从数据库文件表中获取文件大小，计算总共应该有多少分片
    • 获取并解析bitmap，添加分片信息到List<Integer>中，并返回
  • 获取总分片数量
  • 根据列表.size()和总分片数量校验是否所有分片上传成功

获取文件上传状态

@GetMapping(“/status”)，controller接收参数：md5、userId

  1. 试图读文件表，看有没有文件信息
  2. 获取分片信息
  • 获取已上传分片列表
    • 从数据库文件表中获取文件大小，计算总共应该有多少分片
    • 获取并解析bitmap，添加分片信息到List<Integer>中，并返回
  • 获取总分片数量
  • 根据列表.size()和总分片数量校验是否所有分片上传成功

执行minio合并

@PostMapping(“/merge”)，controller接收参数：文件名、md5、用户id

  1. 获取文件类型

  2. 检查文件完整性和权限

  3. 获取分片列表、分片总数量，校验分片是否全部上传成功

  4. 调用service的mergeChunks方法，传入md5、文件名、userid进行分片合并

    • 从数据库中查询所有分片信息

    • 检查分片是否全部上传成功

    • 获取所有分片文件路径

    • 检查minio中是否所有分片都存在

      • 构建合并后的文件路径：String mergedPath = "merged/" + fileName;
        • 传入所有分片路径表 + 合并后的文件路径，调用minioClient.composeObject()执行合并

    • 根据分片路径表，清理minio中的分片

    • 构建redis key，删除redis中的分片上传状态信息（删除key）

    • 将文件表中的文件状态改为1（已完成）

    • 生成有效期1小时的预签名url，并返回这个url

  5. 发送任务给kafka

    • 获取前端会给出的MD5还有文件名

    • 从数据库fileUploadRepository（文件表，不是分片表）中读取分片对应的userId、tag、ispublic信息

    • minio合并返回的url

  • 上述数据一起打包发给kafka，执行文件下载 –> 解析 –> 向量化一系列流程

补充表结构

分片状态信息由redis维护

tag信息存储在文件表、向量表中，分片表无需存储这些信息用于过滤

（只有完整文件、向量检索用的分块 ==> 需要权限过滤）
