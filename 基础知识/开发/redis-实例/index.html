整合redis

  1. 在pom.xml中添加redis依赖

默认情况下，springboot使用lettuce作为redis连接池，可以避免频繁创建or销毁连接

  • Redis 连接的建立和销毁是比较耗时的操作。连接池的作用是预先创建并管理一批 Redis 连接，需要时直接从池里拿，用完放回，避免频繁创建销毁连接，从而大幅提升性能

🌟 添加依赖：Lettuce 的连接池功能依赖于 Apache Commons Pool2 这个工具库如果不添加这个依赖，即使在配置文件里写了 lettuce.pool.enabled: true，连接池也不会生效，Spring Boot 会直接忽略你的连接池配置

  1. 在application.yaml中添加redis配置
  1. 启动redis服务

默认端口6379

  1. 编写redis测试类

RedisTemplate和StringRedisTemplate是springboot预先初始化好的redis连接工厂，可以快速对redis操作。

  • RedisTemplate：泛型类，可以操作任意类型数据
  • StringRedisTemplate：只能操作字符串类型数据

操作redis

如何使用RedisTemplate和StringRedisTemplate操作redis的字符串、列表、哈希、集合、有序列表

1. 字符串

可以存储任意类型的数据

其中opsForValue()获取redis字符串操作对象

  • set()：设置键值对
  • get()：获取键对应的值

redis是内存数据库，目标是块，键值对是实现高性能的有效选择

  • 可以通过key直接定位value
  • 不需要维护表结构、索引、事务日志等

这个键值对是广义的

  • key永远是字符串
  • value可以是string、Hash、List、Set、Zset等结构

对于string类型举例：
接口缓存：

  • key：api:user:info:123
  • value：{"id":123,"name":"张三"}

2. 列表

一个有序的字符串列表，可以存储多个字符串

使用opsForList()方法获取redis列表操作对象

  • rightPush()：向列表右侧添加元素
  • range()：获取列表指定下表范围内的元素

3. 哈希

可以存储多个字段和对应的值

使用opsForHash()方法获取redis哈希操作对象

  • put()：向哈希中添加字段和对应的值
  • get()：获取指定字段的值

4. 集合

无序的字符串集合，可以存储多个字符串

使用opsForSet()方法获取redis哈希操作对象

  • add()：向集合中添加元素
  • members()：获取集合中所有的元素

5. 有序集合

有序的字符串集合，可以存储多个字符串，每个字符串都有一个分值，可以根据分值排序

使用opsForZset()方法获取redis哈希操作对象

  • add()：向列表中添加元素和分值
  • range()：获取列表指定下标范围内的元素

注入redisTemplate

  1. 核心矛盾：静态工具类 vs Spring Bean
  • RedisClient 是一个静态工具类（里面全是静态方法，比如 hIncr、hGet）
    • 方便在任何地方直接调用，不需要依赖注入
  • RedisTemplate 是 Spring 容器管理的 Bean
    • 需要通过 @Autowired 等方式注入，不能直接在静态方法中使用。

如果直接在静态方法里 new RedisTemplate()，会丢失 Spring 自动配置的连接池、序列化方式等特性，所以必须把 Spring 管理的 RedisTemplate 交给静态工具类使用

因此做一个RedisClient类：

  1. 静态变量接收 Bean：RedisClient 中定义一个静态变量 template，用来保存 Spring 管理的 RedisTemplate 实例。
  2. 静态方法注册 Bean：通过 register 静态方法，将 Spring 注入的 RedisTemplate 赋值给静态变量。
  3. 配置类触发注册：ForumCoreAutoConfig 作为 Spring 配置类，在构造方法中接收 Spring 自动注入的 RedisTemplate，并调用 RedisClient.register() 完成静态注册

好处：

  • 保持工具类的易用性：业务代码可以直接 RedisClient.hIncr(...) 调用，无需依赖注入，降低了使用门槛
  • 复用 Spring 自动配置：RedisTemplate 由 Spring 自动初始化并配置连接池、序列化方式，避免了重复造轮子
  • 全局唯一实例：整个项目只有一个 RedisTemplate 实例被注册到 RedisClient，避免了多实例导致的连接池资源浪费
  • 解耦配置与使用：ForumCoreAutoConfig 负责注册，RedisClient 负责提供操作方法，职责清晰，符合「单一职责原则」
