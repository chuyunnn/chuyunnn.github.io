用户登陆注册逻辑总结

Created2026-03-24|Updated2026-04-01|基础知识开发
|Post Views:

1. 密码加密：用spring security 内置的BCrypt加密算法

每次生成一个随机的盐，用这个盐对密码进行加密，存储加密后的内容+盐。后面对明文密码，取出对应的盐，判断加密后是否一致。

2. 用户角色设置、组织标签设置

角色 ==> USER，组织标签：先生成一个用户的私人组织标签（PRIVATE+username），然后缓存到redis里面（私有组织org_tags + 主组织primary_org）

3. 分页查询用户：

前端传一个页数，后端返回对应的信息

因为有组织标签信息，所以写的逻辑是把数据全部查出来，然后过滤，效率是比较低的

如果没有组织标签，可以直接用JPA分页查询

[!NOTE]

JPA：无需写SQL，对于简单的增删改查指令开发很快，但是复杂查询的逻辑比较笨

复杂查询还得用mybatis手写xml sql语句

4. JWT token生成逻辑

（第一次访问，服务端生成JWT并返回：）从**配置文件中取出密钥字符串**，转成jwt能用的加密钥匙 ==> 根据userId去数据库中查找出用户信息 ==> 将信息装进jwt里面（tokenId、role、userId、组织标签信息、主组织标签信息） ==> 缓存token 到redis

（后续请求到达服务器：由jwt过滤器对用户token进行验证）

检查是否需要刷新：（**Filter**，前端任何请求都要先经过filer才到controller）

  • 检查token是否有效
  • 检查离过期时间是不是只剩下五分钟（需要预刷新） / （已过期）过期是否小于10分钟 ==>(yes) 生成全新的JWT
  • 将用户认证信息放到spring security的上下文中（ThreadLocal）

💡 结果：如果一直用，就不会过期。如果长时间不用，就会过期。

  • 如果Access Token彻底过期（上述内容救不回来），采用refresh token换新的
    • 后端返回token失效，前端请求/refresh进行刷新

Access Token：30分钟，Refresh Token：7天，redis有效期长五分钟，防止jwt没过期，redis过期了

🌟 补充：

  1. redis的key：String key = USER_TOKENS_PREFIX + userId + “:tokens”;
  2. redis数据结构：Set类型（可以存放多个值，不会重复，适合存一个用户的多个Token，且一个token不会存多次）
    • 同一个用户，不同设备登陆
    • 多次登陆刷新会产生新的jwt
    • 无感刷新时新旧token会共存

5. 组织标签过滤

这个 OrgTagAuthenticationFiler 过滤器把用户id**放到servlet容器提供的key-value桶（request属性里面）**

理由：

  1. 比较轻量，没有spring security的Authentication字段这么重

    • springcontext就是一个线程绑定（Threadlocal）容器，生命周期一般和一个请求线程同步

  2. 业务逻辑只需要一个userid字符串的时候，用request可以实现快速获取

    • public ResponseEntity<?> uploadChunk(
    @RequestAttribute("userId") String userId,  // ← 直接从 request 属性获取
    @RequestParam("file") MultipartFile file) {

[!NOTE]

Servlet容器（Web容器），是运行java web应用程序的运行环境，如Tomcat、jetty或者Undertow

filterChain.doFilter直接用责任链模式执行过滤

Threadlocal && Request

都使用过滤器 Filter 拦截

绝大多数逻辑从request中获取信息就行。有两个地方用到了Threadlocal：

  1. MDC（LogUtils日志上下文）：

    • 作用：为每个请求添加日志字段
    • 原理：
      • MDC (Mapped Diagnostic Context) 是 基于 ThreadLocal 实现的
      • 是SLF4J 提供的线程隔离的 Map 结构
    • 方法：在LogUtil的工具类里面定义不同方法，然后在代码里面直接 LogUtil.方法() 调用即可

  2. Agent中用于上下文传递userId

    • 理由：websocket不是http request
