事务相关逻辑整理

Created2026-04-01|Updated2026-04-01|基础知识开发
|Post Views:

其实是不同东西（锁、redolog、undolog、MVCC）来实现事务：

使用 @Transactional 来声明事务即可

InnoDB 会根据你的 SQL 语句 和 隔离级别 自动加锁

项目中用到事务的地方：

1. UserService（用户服务） - 最核心的事务使用者

位置： UserService.java

使用事务的方法：

  • registerUser()
    • 用户注册流程
    • 操作：创建用户、创建私人组织标签、设置主组织标签
    • 涉及多次数据库写入操作，需要事务保证一致性
  • createOrganizationTag()
    • 创建组织标签
    • 操作：验证权限、检查重复、保存标签、清除缓存
  • assignOrgTagsToUser()
    • 为用户分配组织标签
    • 操作：验证权限、更新用户标签、设置主组织、更新缓存
  • updateOrganizationTag()
    • 更新组织标签信息
    • 操作：验证权限、检查循环引用、更新标签、清除缓存
  • deleteOrganizationTag()
    • 删除组织标签
    • 操作：验证权限、检查关联、删除标签、清除缓存

2. DocumentService（文档服务）

位置： DocumentService.java

使用事务的方法：

  • deleteDocument()
    • 删除文档及其相关数据
    • 操作顺序：
      1. 删除 Elasticsearch 中的数据
      2. 删除 MinIO 中的文件
      3. 删除 DocumentVector 记录
      4. 删除 FileUpload 记录
    • ⚠️ 注意： 即使某一步失败，也会继续执行后续操作（try-catch 包裹）

3. UploadController（上传控制器）

位置： UploadController.java

使用事务的方法：

  • mergeFile()
    • 合并文件分片
    • 操作：检查分片完整性、合并文件、发送 Kafka 消息
    • 使用 kafkaTemplate.executeInTransaction() 保证 Kafka 消息发送的事务性

4. DocumentVectorRepository（文档向量仓库）

位置： DocumentVectorRepository.java

使用事务的方法：

  • deleteByFileMd5()
    • 原生 SQL 删除操作
    • 使用 @Modifying + @Transactional 组合
    • 执行原生 DELETE 语句

5. 测试类 TransactionTestService

位置： TransactionTestService.java

用途： 用于测试事务边界和自调用问题

  • protectedTransactionalMethod()
    • 演示 protected 方法的事务行为
    • 展示了自代理注入 (@Lazy) 来解决事务失效问题

事务使用特点

优点：

  1. 合理的职责划分
    • 事务主要用在 Service 层（业务逻辑层）
    • Repository 层仅在原生 SQL 操作时使用
  2. 多步骤操作的原子性保证
    • 用户注册：创建用户 + 创建组织标签
    • 文档删除：多个数据源的删除操作
    • 组织标签管理：验证 + 操作 + 缓存清理
  3. 跨资源事务处理
    • UploadController 中使用 Kafka 事务消息
    • 保证了数据库操作和消息发送的一致性

⚠️ 注意事项：

  1. 异常处理策略
    • DocumentService.deleteDocument() 中即使某步失败也继续执行
    • 这可能导致数据不一致（部分删除成功，部分失败）
  2. 未显式指定回滚规则
    • 所有 @Transactional 都使用默认配置
    • 默认只在 RuntimeException 时回滚，checked exception 不回滚
  3. 事务传播行为
    • 未显式指定 propagation，默认使用 REQUIRED
    • 大多数场景合适，但某些只读查询可以考虑使用 REQUIRES_NEW 或 NESTED
