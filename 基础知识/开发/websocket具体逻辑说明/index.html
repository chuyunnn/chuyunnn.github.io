HTTP && Websocket

http做不到：

  1. 流式输出
  2. 后端异步处理完成后，主动通知前端

💡 ==> 使用websoket

HTTP：

  • 特性：无状态、短连接 ==> 用户发一个 Request，服务器回一个 Response，连接立即断开。

映射：Spring 通过 @RequestMapping 这种“地址簿”就能精准找到对应的 Controller 方法。

**WebSocket (Handler)**：

  • 特性：有状态、全双工长连接 ==> 连接一旦建立（Handshake），通道就一直开着。服务器可以主动给用户发消息，用户也可以随时发消息。

映射：由于连接是持续的，Spring 无法像 HTTP 那样每次都重新“路由”方法。它需要一个专用的处理器类（Handler）来维持这个会话（Session）的生命周期。

💡 ==> 使用handler处理websoket连接

具体流程

WebSocketConfig.java

在配置类里src/main/java/com/yizhaoqi/searchSmart/config/WebSocketConfig.java

  1. @Configuration 表示这是一个配置类

    • 使用CGLIB动态代理类，也就是每次拿到的都是同一个单例对象，而不会重复创建
    • Spring Boot启动时，会扫描所有带有 @Configuration 注解的类
      • 注册url，绑定Bean：AgentWebSocketHandler、ChatWebSocketHandler
      • 💡 后续：用户发起 ws://localhost:8080/ws/chat 请求 ==> Spring 发现这个路径被注册到了 ChatHandler ==> 握手成功后，这个连接就“赖”在 ChatHandler 里了 ==> 之后用户发的每一句话，都会触发 ChatHandler 里的 handleTextMessage 方法。

  2. @Component 表示创建类对象，放入IOC容器

    • 派生：@Controller、@Service、@Repository
      • 底层本质：源码都标了 @Component，功能一样，只是为了分层好读

  3. @Autowired 表示注入使用@Component 注入IOC的Bean

  4. @Bean：如果是第三方工具类，不能用@Component ，只能用 @Configuration + @Bean

使用session管理

因为websocket需要简历长连接，所以需要session来管理session对象，这样服务端准备好数据之后，可以找到是哪个人要的请求，然后发回去

使用ConcurrentHashMap 进行管理，它是线程安全的HashMap

  • 使用**分段锁orCAS模式（乐观锁），支持高并发**：允许一个线程读A区时，另一个线程读B区
    • 比hashtable性能好（会锁死整个表） ==> 底层和hashmap一样，在几乎所有方法上加了synchronize锁
