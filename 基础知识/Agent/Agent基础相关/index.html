Agent基础相关

Created2026-02-05|Updated2026-02-27|基础知识Agent
|Post Views:

Agent可以完成一个有目标、有步骤的任务

从生成内容 ==> AI判断该不该做、做什么 + 程序决定能不能做、怎么做 【 工具调用 】

java开发框架：SpringAI、LangGraph4j

多步骤任务（Stateful Task）

需要分步骤完成 ==> 每一步都依赖前一步的结果，并且中间结果必须和真实系统交互（不是模拟的）

因此，这类任务本质上是一段过程，不是一次回答

💡 一个Agent至少需要具备三层最基本的“任务意识”：

  1. 目标意识

    • 我现在要完成的任务是什么？

  2. 状态意识

    • 我已经做到哪一步了？

    • 当前手里有什么信息？

  3. 行动意识

    • 接下来应该做什么？

    • 是否需要调用工具？

    • 是否可以结束任务？

正是这三层意识，让 Agent 从“回答者”，变成了“执行者”。

和 WorkFlow（工作流） 的区别

Workflow：固定流程的执行模式

Workflow中，整个执行流程是提前设计好的（固定的），模型只是在某些节点被调用

例如：

  1. 查询数据库
  2. 调用模型分析数据
  3. 调用发邮件接口

模型在Workflow中，不决定“下一步是什么”，只是被动参与某一步

Workflow的优点是：可控、稳定、易于调试，但它的灵活性非常有限

Agent：模型对过程拥有决策权

Agent中，模型不再只是被调用的工具，它需要根据当前状态，决定下一步行动（动态的）

Agent 会持续思考：

  • 当前目标是否已经完成
  • 现有信息是否足够
  • 是否需要调用工具
  • 是否需要继续推进，还是可以结束

换句话说，Workflow 决定“怎么做”，Agent 决定“下一步做什么”，这也是判断一个系统是否“Agentic”的最核心标准之一。

Agent的几大流程

比如处理今天天气怎么样

THINKING 思考阶段

分析问题，思考需要什么信息

EXECUTING 执行阶段

调用工具

FINISHED 整合回答

整合成自然语言

ERROR 出错

Agent的真正能力 = 工具执行能力 + 知识检索能力

只有当Agent既知道”如何做事”（工具），又知道”该做什么事”（RAG检索相关知识） ==> 成为真正有效的”执行者”，而非仅仅是”回答者”

💡 这构成了现代Agent系统的两大支柱：能力调用系统和知识检索系统

当工具越来越多

怎么统一描述？每个工具需要哪些参数？新增一个工具，要不要改一堆提示词？工具只能是我项目里的函数吗？能不能用别人已经写好的工具？

如果这些问题都靠“临时约定”解决，工具本身就会变成新的复杂源头

==> 问题已经不再是“怎么写函数”，而是：怎么管理工具这个概念本身

在早期的工具调用设计中，工具往往等价于项目里的一个函数或某个类的方法，但随着 Agent 系统复杂度提升，一个非常重要的变化开始出现：工具，不一定非得存在于你的代码里

  • 从系统角度看：查询数据库、发邮件、调用第三方接口 都是不同的能力

至于这项能力是本地函数、远程服务、还是别人写好的现成系统，对 Agent 来说都不重要

💡 重要的是：能力如何被描述，如何被发现，以及如何被安全地调用

MCP（Model Context Protocol）

统一协议，解决了工具的组织、发现和调用问题，用来解决一个核心问题：如何把工具从“项目内部的函数”，变成“可被 AI 统一使用的外部能力”

在MCP的模式下，工具可以是独立运行的服务，无论来源，只要遵循同一套约定，Agent就可以看见并使用它们

==> Agent 不再依赖“写了什么函数”，而是依赖“系统对外暴露了什么能力”

如果把这一章的内容串起来，会发现一条非常清晰的演化路径：

  1. 一开始，只是想让 AI 能“调用函数”
  2. 接着，希望工具能被更好地描述和约束
  3. 再往后，希望工具可以被复用、共享、独立运行
  4. 最终，把工具抽象成“能力”，并通过统一协议暴露

Tool Calling解决的是“能不能调用”，而 MCP 关注的是“能力如何被组织和管理”

Agent能力链条

[!IMPORTANT]

  • 模型：负责理解与生成
  • Agent：负责目标与过程推进（持续运行的决策单元）
  • 工具 / MCP：让AI能影响真实系统
  • 向量模型 + RAG：让AI在需要时，知道该知道的事（提供信息）

**Agentic System **智能体系统：当一个Agent不够用

随着任务复杂度的提升，一个Agent未必适合做所有事情

比如，有些任务更偏向：计划与拆解、信息检索、数据分析、结果总结

当系统中出现多个职责清晰的Agent相互配合完成同一个目标 ==> Agentic System（智能体系统）

💡 Agentic 系统讨论的，不是用哪个模型，写什么提示词，而是更偏系统级的问题。

比如：

  • 如何拆解任务
  • 如何管理状态
  • 如何控制不确定性
  • 如何让多个Agent 协作
  • 如何让 AI 在确定的系统中稳定运行

从这个角度看，Agentic 其实是后端领域的问题
