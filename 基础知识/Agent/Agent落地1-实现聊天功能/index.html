Agent落地1-实现聊天功能

Created2026-03-02|Updated2026-03-02|基础知识Agent
|Post Views:

这是一个最小 Agent 实现，目标为：集成 LLM，能够完成最基本的聊天功能

在这个版本中，只保留 Agent 的基本功能即可

chatMemory

模型的上下文记忆是系统完成的，这一步就是在限制最多保存的消息数量【通过滑动窗口的方式保留最近N条消息】

💡 控制每次发给 AI 模型的 Prompt 里，包含多少条历史会话上下文

  • 不是 “系统自动完成” 的，而是需要你手动把 ChatMemory 里的上下文提取出来，组装到 Prompt 中

    • Spring AI 提供了便捷工具简化这个过程

  • “滑动窗口”就是当历史消息超过设定的上限时，自动删除最早的消息，只保留最近 N 条

    • 本质是控制 Prompt 的长度，避免 Token 超限

使用：

Spring AI 会**自动配置一个 ChatMemory Bean，默认实现就是 MessageWindowChatMemory**，并使用内存存储（InMemoryChatMemoryRepository）

==> 只需要通过依赖注入（如 @Autowired）就能直接使用它，无需手动创建实例

这段代码的作用是：在对话开始时，将系统提示（System Prompt）添加到当前会话的记忆中

这里的 this.chatMemory 可以是 Spring AI 自动配置的，也可以是手动定义的，代码本身不关心具体实现，只依赖 ChatMemory 接口，这体现了面向接口编程的优势

chatClient

  • ChatClientRegistry：一个 “模型注册表 / 仓库”，里面存放了多个 ChatClient 实例（比如一个绑定 OpenAI、一个绑定讯飞星火、一个绑定百度文心），每个实例都有自己的唯一名称（如 “openai”、”xinghuo”、”ernie”）。

  • ChatClient：操作单个模型，拿到哪个模型的 ChatClient，调用它的 call() 方法就会直接访问对应的模型，不需要再指定名称

使用：自动注入指定名称的 ChatClient

Spring AI 支持通过 @Qualifier 注解，直接注入 Registry 中指定名称的 ChatClient
